# 连锁酒店智能客服售前 PPT 预览

合成客户：220家门店，电话、OTA和公众号三类入口，夜间咨询占31%，重复问题集中在发票、停车和延迟退房。前5页只讲客户，不讲供应商。

| 页段 | 核心叙事 | 关键页标题 |
|---|---|---|
| 1—5 客户问题 | 咨询分散、夜间无人、标准不一 | “客人问的是同一件事，得到的却是220种答案” |
| 6—9 方案 | 统一知识、转人工、质检闭环 | “机器人先接住，复杂问题带上下文交给人” |
| 10—12 案例 | 三类合成门店场景 | “发票咨询平均处理从6分钟降到2分钟” |
| 13—16 部署 | 试点、集成、灰度、培训 | “先用20家店验证八周” |
| 17—18 ROI | 假设透明 | “回收期取决于转人工率，不藏假设” |
| 19—20 异议 | 价格、供应商、安全 | 问答卡 |

## ROI 演示

假设月咨询10万次、40%为标准问题，自动解决率50%，单次人工成本3元，则月节省约6万元；再扣系统和运营成本。该算法未计体验收益，也没有把所有咨询都算成节省。

## 三个异议

- **已有供应商：**先接入现有工单，不要求一次替换；
- **价格贵：**用20店试点的实际转人工率和人工成本决定是否扩；
- **数据安全：**明确数据范围、权限、留存、审计与退出时删除证明。

所有客户背景、同行案例和量化效果均为合成预览。正式材料必须联网核实客户公开信息，并由客户确认现状假设。
